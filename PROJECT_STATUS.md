# Project status

Agent orchestration system. Written 2026-11-15 from AUDIT.md; `tests/test_project_status_accuracy.py` fails if this page and AUDIT.md drift apart. Full audit: AUDIT.md. Decisions: CLAUDE.md.

## 1. WHAT THIS SYSTEM IS

- Spec-driven tool generation: any system that has a spec (or an OpenAPI document, a recorded trace or pasted docs that become one) gets an MCP server and its tests from `generators/from_spec.py`, with one shared contract test.
- An orchestrator that drives any combination of industries through those tools, with one error contract and a human handoff with full context; it names no industry.
- A duty layer: reviewed, named tool sequences that run in preference to fresh planning, and that are learned from successful runs and installed only by a person.
- Write-safety that refuses by default: no tool that changes the world runs unless its server's own metadata classes it and the run, an approver or a reviewed duty allows it.
- A learning loop that turns recurring failures into spec patches as proposals; nothing is applied until a named human approves it.
