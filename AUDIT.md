### 3d. Known hazards

- Environmental clock event. What it is: a pause of the process or the machine (sleep, VM pause; D17 (9), (12)), which advances both the wall and the monotonic clock, so a test can appear to run for minutes or hours. How it is detected, four signals (D17 (12)): negative elapsed time; a negative remaining time in a failure's text; a wall/monotonic disagreement above 5 s; a heartbeat thread with 0.5 s ticks whose gaps above 5 s mean the process was not scheduled (heavy CPU load does not do that: the 36-burner runs never tripped it). What the runner does: a FAILED test in such a window is reported as SKIPPED with the reason `environmental interruption: <reason>; run_id=...`; the closing line begins `INVALID RUN (clock event): N environmental interruption(s), run_id=...`; the exit status is non-zero (an invalid run is never green); the run is not recorded in `.perf/history.json`. Known cost: a REAL failure that happens to coincide with a pause is also skipped; the run is flagged invalid and exits 1, and a re-run shows the real failure. Also: a test that fakes a clock by patching `time.monotonic` or `clock_guard.elapsed` globally is itself seen by the real detector; fake clocks must be injected.
- Windows Application Control blocks `import anthropic` on the build machine (its `jiter` DLL is blocked), so the repository uses a plain-httpx Messages API client (the ingest.anthropic_http module, shared by the doc path and the planner). `ANTHROPIC_AUTH_TOKEN` is no longer accepted: setting it without `ANTHROPIC_API_KEY` raises a loud error naming the fix (D16, D20).
- Laptop sleep. A sleep mid-run produced a 47,090 s (13 h) suite run once and corrupted the first budget derivation (D17 (7)); the measuring script now excludes any run over 3x the median run and any record over 10x its own budget. A sleep during a normal pytest run is handled by the clock-event machinery above.
- Budgets are quiet-state. A plain `pytest` run on a loaded host prints "budget overrun warnings" and exits 0 (D17 (11)); the strict gate (`--strict-budgets`, used by CI) fails the same overrun by name. On a loaded host use the `--verify --allow-loaded` mode (3x).
- Strict CI can flake on tests that have no measured budget: they run under the default 2 s guard. Evidence in `.perf/overruns.jsonl` on this machine: `tests/learning/test_apply.py::test_second_verify_crash_also_restores_everything` warned at 2.188 s against its default 2.0 s budget (a 1.09x overrun) on 2026-11-10, and `test_header_carries_spec_hash_and_total_recurrence[records0-add_error_code]` warned at 2.172 s. Such a test would FAIL under `--strict-budgets`.
- The learning loop is blind to travel, retail and banking (no specs, so no proposals possible); `learning.collect` prints `systems without specs (no proposals possible): banking, retail, travel.` at start (D18).
- Doc-ingested specs are drafts, not trusted specs: every one carries `source: doc-unverified` and the pipeline prints a warning whenever it handles one (D16).
- Found during the Package 7 onboarding check (2026-11-11), recorded here and NOT fixed (no features in that package): (1) the heartbeat detector fired on runs with no known sleep, twice: a cold-start agent's full suite run while another suite ran at the same time (247 s, `INVALID RUN (clock event): 1 environmental interruption(s)`), and the nested run of the audit-accuracy slow test (a 58.0 s heartbeat gap, the test itself passed; a re-run on the same host was clean at 50.6 s). D17 (12) says heavy CPU load does not trip the detector (the 36-burner runs never did); these two events show it can fire under multi-process contention, so either those were real pauses (not shown) or the detector can false-positive. Pattern across the four pauses seen in this package (58 s, 247 s, 267 s, 424 s; the first D17 event was 267.8 s): each coincided with a command that ran near or beyond the shell's ~180 s foreground limit and was moved to the background. HYPOTHESIS, not tested: the harness suspends or throttles the child process at that moment, which would also explain the original -267.8 s event (D17 (9)). A test would be a long `sleep`-style command run in the foreground and in the background with the heartbeat watching; not done. Unresolved; treat an INVALID RUN as "re-run alone on an idle machine". (2) A strict run reported a budget ERROR for `tests/test_pipeline_relative_url.py::test_openapi3_with_relative_server_url_is_refused_with_an_actionable_reason` at 2.078 s against its default 2 s: another test on the default budget with no measured value, the same class as the one above. (3) `scripts/measure_budgets.py --verify` printed "No timed test is above 75% of its budget" in a run whose suite had an ERROR for a test not in its timed table; the headroom line describes only the tests it times, not the suite's exit status, and reads oddly next to a failing run. (4) The cold-start subagents were told not to read CLAUDE.md, but the harness injected its text into their context, so "no prior context" is not fully enforceable here; their findings are still real command failures, but a step they call clear may have been clear because of that.
